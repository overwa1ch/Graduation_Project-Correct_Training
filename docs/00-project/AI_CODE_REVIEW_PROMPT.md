# AI 代码漂移检查提示词

完成功能实现后，使用以下提示词让 AI 自动检查代码是否存在漂移问题。

---

## 🚀 快速检查（复制粘贴即可）

```
请帮我检查刚才实现的代码是否存在代码漂移问题。

检查范围：
1. 是否在 aiwa_app 中重新实现了 aiwa_core 已有的功能？
2. 代码是否放在了正确的位置（aiwa_core vs aiwa_app）？
3. 是否使用了 aiwa_core 的统一导出（import 'package:aiwa_core/aiwa_core.dart'）？

请参考：
- docs/00-project/ARCHITECTURE_BOUNDARIES.md（架构边界规则）
- aiwa_core/lib/*/README.md（核心库功能文档）

检查以下文件：
[在这里粘贴你刚修改的文件路径和关键代码片段]
```

## 🎯 使用场景

### 场景 1：刚实现了一个新功能

**提示词**：
```
我刚实现了 [功能名称]，请检查是否存在代码漂移：

文件：[文件路径]
功能：[功能描述]

请检查：
1. 是否应该放在 aiwa_core 而不是 aiwa_app？
2. 是否重复实现了核心库已有的功能？
```

### 场景 2：重构现有代码

**提示词**：
```
我正在重构 [文件路径]，请检查重构后的代码是否符合架构边界：

重构前：[简要描述]
重构后：[简要描述]

请检查：
1. 重构后的代码位置是否正确？
2. 是否应该迁移到核心库？
```

### 场景 3：不确定代码归属

**提示词**：
```
我不确定这段代码应该放在哪里，请帮我判断：

代码功能：[功能描述]
当前位置：[文件路径]

请参考 ARCHITECTURE_BOUNDARIES.md 的决策树，告诉我应该放在：
- aiwa_core（如果是核心算法/业务逻辑）
- aiwa_app（如果是 UI/平台特定功能）
```

---

## 💡 检查要点

AI 会重点检查以下内容：

1. **重复实现检测**
   - 角度计算、平滑算法、计数逻辑
   - 质量评估、Schema 验证
   - 关键点名称常量、结果模型解析

2. **位置判断**
   - 核心算法 → aiwa_core
   - UI/平台 → aiwa_app

3. **导入方式**
   - 是否使用统一导出：`import 'package:aiwa_core/aiwa_core.dart';`
   - 是否避免分散导入

4. **禁止区域**
   - aiwa_core 是否包含 Flutter 依赖
   - aiwa_app 是否重复实现核心算法

---

## 📝 使用建议

1. **每次完成功能后立即检查**，避免问题积累
2. **粘贴关键代码片段**，让 AI 能准确分析
3. **参考架构文档**，确保 AI 使用正确的规则
4. **记录检查结果**，形成知识积累
