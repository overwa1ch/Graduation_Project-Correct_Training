# 统一取消令牌架构实施报告

## 执行摘要

已实施跨层统一取消令牌架构的 Phase 2（原生层集成），Phase 1（Dart 层统一）部分完成。报告包含当前实现状态、架构设计与后续工作建议。

---

## 一、架构概览

### 1.1 核心设计理念

- 不可变状态对象：`CancellationToken` 在任务创建时生成，取消时更新状态，各层共享同一实例
- 统一检查点：所有层次使用 `token.isCancelling` 作为取消检查标准
- 跨层传播：取消信号从 Dart 层 → 原生层，确保所有组件响应

### 1.2 架构层次划分

```
┌─────────────────────────────────────────────────────────────┐
│ 层次1: Dart 应用层 (UI/业务逻辑)                            │
│ - AnalysisSessionManager                                     │
│ - AnalysisSession                                            │
│ - CancellationToken 创建与管理                               │
└─────────────────────────────────────────────────────────────┘
                          ↓ 传递 token
┌─────────────────────────────────────────────────────────────┐
│ 层次2: Dart 服务层 (VideoAnalysisService)                     │
│ - VideoAnalysisService.analyzeVideo()                        │
│ - _runVideoAnalysis()                                         │
│ - _extractFrames() / _inferPoses()                            │
│ - 所有检查点使用 token.isCancelling                           │
└─────────────────────────────────────────────────────────────┘
                          ↓ 传递 token
┌─────────────────────────────────────────────────────────────┐
│ 层次3: Dart-原生桥接层 (NativeFrameExtractor)               │
│ - extractFramesWithProgress(token)                            │
│ - cancelExtraction(tokenId)                                   │
│ - 定期检查并调用原生层取消                                    │
└─────────────────────────────────────────────────────────────┘
                          ↓ MethodChannel (tokenId)
┌─────────────────────────────────────────────────────────────┐
│ 层次4: 原生层 (Android/iOS)                                  │
│ - MainActivity/AppDelegate: 取消标志管理                     │
│ - VideoFrameExtractor: 循环中检查取消                         │
└─────────────────────────────────────────────────────────────┘
                          ↓ (无法控制)
┌─────────────────────────────────────────────────────────────┐
│ 层次5: 第三方库层 (ML Kit)                                    │
│ - 无法真正中断，只能跳过后续调用                              │
└─────────────────────────────────────────────────────────────┘
```

## 四、架构设计详情

### 4.1 CancellationToken 设计

```dart
class CancellationToken {
  final String id;              // 唯一标识（通常 = sessionId）
  final String sessionId;       // 关联会话ID
  bool _isCancelling = false;   // 私有状态（不可逆）
  
  bool get isCancelling;        // 检查取消状态
  void cancel();                 // 标记为取消
}
```

设计要点：
- 不可逆：一旦取消无法恢复
- 线程安全：Dart 单线程模型保证安全性
- 轻量级：仅包含状态标志，无复杂逻辑

### 4.2 取消传播流程

```
用户取消
  ↓
AnalysisSession.cancel()
  → token.cancel()  [⚠️ 当前未实现]
  ↓
VideoAnalysisService 检测 token.isCancelling
  → 在所有检查点提前退出  [⚠️ 当前未实现]
  → NativeFrameExtractor.cancelExtraction(tokenId)  [✅ 已实现]
  ↓
原生层收到 cancelExtraction 调用
  → cancellationFlags[tokenId] = true  [✅ 已实现]
  ↓
原生层循环检查 isCancelled()
  → 检测到 true，提前退出循环  [✅ 已实现]
```

## 五、关键实现细节

### 5.1 Dart 层（NativeFrameExtractor）

```dart
// 定时检查取消状态
if (token != null) {
  cancellationCheckTimer = Timer.periodic(
    const Duration(milliseconds: 100),
    (_) {
      if (token?.isCancelling == true && tokenId != null) {
        cancelExtraction(tokenId);
      }
    },
  );
}
```

特点：
- 每 100ms 检查一次（最多 100ms 延迟）
- 自动调用原生层取消方法
- Stream 取消时也触发原生取消

### 5.2 Android 原生层

```kotlin
// 线程安全的取消标志存储
private val cancellationFlags = ConcurrentHashMap<String, Boolean>()

// 取消检查 lambda
val isCancelled: () -> Boolean = {
    actualTokenId.isNotEmpty() && 
    (cancellationFlags[actualTokenId] == true)
}

// 循环中检查
for (i in 0 until totalFrames) {
    if (isCancelled()) {
        return  // 提前退出
    }
    // ... 提取帧
}
```

特点：
- `ConcurrentHashMap` 保证线程安全
- 每帧检查一次，响应快速
- 资源自动清理

### 5.3 iOS 原生层

```swift
// 线程安全的取消标志存储
private var cancellationFlags: [String: Bool] = [:]
private let cancellationQueue = DispatchQueue(
    label: "com.example.aiwa.cancellation",
    attributes: .concurrent
)

// 取消检查 closure
let isCancelled: () -> Bool = {
    guard !tokenId.isEmpty else { return false }
    var cancelled = false
    self?.cancellationQueue.sync {
        cancelled = self?.cancellationFlags[tokenId] == true
    }
    return cancelled
}
```

特点：
- 并发队列 + barrier 标志保证线程安全
- 递归函数开始和继续前都检查
- 资源自动清理

## 六、已知问题与限制

### 6.1 当前问题

1. **代码不一致** ⚠️
   - `event_bus.dart` 尝试传递 token，但 `VideoAnalysisService.analyzeVideo()` 方法签名不匹配
   - 需要同步修复方法签名和调用处

2. **取消检测延迟** 
   - 桥接层每 100ms 检查一次，可能存在延迟
   - 原生层每帧检查，延迟可忽略

3. **ML Kit 无法中断** 
   - `detector.processImage()` 一旦开始无法中断
   - 只能在调用前检查，跳过后续帧

### 6.2 设计限制

1. **无确认机制**（Phase 3 特性）
   - 当前不等待原生层发送"已停止"确认
   - 无法追踪哪些组件已停止

2. **无超时保护**
   - 如果原生层崩溃或卡死，可能永久等待
   - 建议后续添加超时机制
